# ReadAll

[English](README.md)

Выберите `src_dir = examples/ReadAll` в `platformio.ini` репозитория, задайте
окружение своей платы и откройте монитор порта на скорости 115200 бод. GPIO
OpenTherm-адаптера задаются через `MASTER_RX_GPIO` и `MASTER_TX_GPIO`.
Включённое окружение ESP32-S3 использует RX=35/TX=36; значения в скетче по
умолчанию — 4/5.

Пример читает все 87 известных ID с доступом R или RW в сводной таблице
OpenTherm v4.2.1. Каждый `loop()` отправляет один синхронный запрос чтения:
до десяти попыток всего, включая первую. Результаты `INVALID`, таймауты и
восстанавливаемые ошибки повторяются; успешный ответ или валидный отрицательный
ответ завершает операцию досрочно. После вывода итогового результата пример ждёт
150 мс перед следующим запросом (ID или индексом). После последнего ID он ждёт
10 секунд и повторяет
список. Поддержка зависит от
подключённого устройства: доступный для чтения ID реализован не в каждом котле.

В каждой строке указаны ID, имя и статус операции в выровненных колонках.
Если получен полный ответ, добавляются его исходный кадр и тип сообщения,
включая `DATA_INVALID` и `UNKNOWN_DATA_ID`. Эти валидные отрицательные ответы
имеют собственные статусы операции; их payload не расшифровывается как успешно
прочитанное значение. `INVALID` обозначает повреждённый ответ или несовпадение ID.
Для успешного результата выводятся данные в шестнадцатеричном
виде с расшифровкой через соответствующий wrapper сообщения. Числовые ID
печатают значение f8.8 либо беззнаковое/знаковое целое число. Структурированные
ID печатают каждое именованное поле и флаг, доступные в их wrapper: все флаги
Status, поля конфигурации, флаги и коды ошибок, разрешения удалённых параметров,
компоненты даты/времени, индексированные значения и другие поля. ID30 использует
существующую в библиотеке интерпретацию f8.8.

Количество TSP и размер истории ошибок определяют число последующих
индексированных запросов. Пример читает индексы `0..count-1`, по одному в
`loop()`, для котла, вентиляции/рекуперации и солнечного накопителя. Нулевой
размер пропускает индексированные запросы группы. Если количество прочитать
не удалось, индекс 0 проверяется один раз. Ошибка отдельной записи не
останавливает остальные индексы. В каждом результате печатается
`requestIndex`; успешный ответ также показывает возвращённые `index` и `value`
через `IndexedValue`.

Индексированные запросы передают индекс в HB и ноль в LB. Остальные запросы
имеют нулевой payload; строки производителя по-прежнему читают символ 0. Запросы
Status передают нулевые флаги мастера, включая разрешения CH и DHW; используйте
пример на тестовом стенде, где такие флаги допустимы. Запросы записи не отправляются.
